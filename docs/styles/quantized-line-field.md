2. 只采样一次路径
使用下方数据中精确的 200×200 站标 Path2D 路径字符串（三张卡共用同一站标，初始化时只采样一次并共享亮度表），并使用对应 scale 居中绘制：将 300 像素临时画布乘以 scale 除以 200，平移到中心，再将路径原点平移 -100,-100。创建一个尺寸为 300×300 的脱离 DOM 的临时 canvas，即 60 个网格单元乘以每格 5 个超采样像素。先填充不透明黑色，再用白色填充站标 Path2D。只读取一次像素数据。对每个 60×60 网格单元，将来源图像中对应的 5×5 像素按 Rec. 709 公式计算，即 0.2126 R + 0.7152 G + 0.0722 B，再除以 255 并求平均，保存为含 3,600 个数值的 Float32Array。之后只保留该数组和卡片元数据。把临时 canvas 的宽高设为 0，并让 context 和像素缓存离开作用域。包括尺寸变化在内，都不得重新采样路径。三张卡的纵横比固定为 0.70：填充站标时在 y 方向按 0.70 预压缩（scale y = scale × 0.70），映射回卡片后恰好恢复原比例，标记不变形。站标中心放在表格高度的 42% 处，底部留给标语。

3. 量化竖线绘制
每张卡片绘制 60 根等距竖列，每列 30 段竖线。每一段取相邻两行网格亮度的平均值。使用 0.12、0.42、0.89 三个阈值量化成且仅量化成四档。线宽只使用 0.38、1.12、2.28、3.80，并乘以「网格单元尺寸除以 5.25」。每段接近两个网格单元高，段间留 0.7 像素窄缝，使用平头线帽；四档透明度依次是 0.15、0.64、0.93、1，让标志像一节节竹段。按粗细档分组，每帧每组只描边一次。卡片顶部的小站标也必须根据已存的亮度表绘制；不能加入 Logo 图片或 SVG 元素。

4. 缓慢、可复现的流动噪声
初始化时使用 xorshift 整数 PRNG，以 seed 7319 生成一张共享的 128×128 随机格点表；每轮依次执行 state ^= state << 13、state ^= state >>> 17、state ^= state << 5。把每个无符号整数除以 4,294,967,295，再乘以 2 并减去 1，得到 -1 到 1 的格点值。用平滑双线性 value noise 取样，先把每个局部小数 t 转换为 t*t*(3-2*t)；每张卡的 seed 作为水平偏移。每段的 x 取「列 × 0.15 + 卡片 seed」，y 取「行 × 0.16 - 经过秒数 × 0.17」，使可见噪声缓慢向下流动。在线宽分档之前，调整后亮度为「亮度 × 0.94 + 噪声 × 0.12 × (0.25 + 亮度 × 0.75)」。鼠标静止时，线条粗细也应轻轻漂移。动画过程中不要调用 Math.random。

5. 指针作用与弹簧复位
用卡片内的 CSS 像素坐标记录指针位置。合并连续指针事件：先保存最新 client 坐标，在下一动画帧中只读一次卡片边界；状态文字只在状态切换时更新。指针进入、触摸或从上一次脉冲位置累计移动超过 1.5 像素时，把脉冲设为 1，让附近线段径向散开。作用半径为站标绘制区域宽度的四分之一。影响系数为 max(0, 1 - 距离/半径)，先平方再乘以脉冲和 25，沿径向产生位移，竖直方向再乘 0.58。位移使用阻尼弹簧模型：刚度 145、阻尼 19，每次积分步长最多 1/30 秒。脉冲按 exp(-dt × 5.5) 衰减后，每段都回到原始网格坐标；即使鼠标停在原处，也不能让线条持续散开。鼠标和触控使用同一套弹簧反馈；键盘聚焦时显示检测框，无须模拟指针移动。

6. 确定性的检测框
检测框必须来自当前的数值线场，不能只在初始化时算出固定坐标，也不调用 AI 服务。覆盖层可见时，扫描间隔至少 100ms。复用一个 60×60 Float32Array，每次扫描先清空；对每段跨两行的可见线条，把当前叠加噪声后的亮度，根据弹簧位移后的位置，用双线性权重分别累积到对应两行网格。仍然只用初始化采样的源数据，不能再次读取画布像素。暂停时，聚焦或尺寸变化可以补做一次静态扫描，但不能连续安排帧。

对这张实时亮度场建立积分图，计算 7×7 窗口的平均亮度，选中后向外扩一格。最亮窗口均值低于 0.04 时不画框；保留得分至少为最亮候选 48% 的区域。空间非极大值抑制使用 16 格中心间距；不足两个区域时放宽为 12 格，最多保留三个。为避免相近分数导致乱跳，可在候选排序中加上 0.025 * exp(-到上一目标的距离平方 / 128) 的小幅连续性权重。将新窗口与 12 格以内的旧目标匹配，保留目标身份、速度和连线顺序。只把检测目标吸附到整数网格，显示框使用刚度 144、阻尼 24 的临界阻尼弹簧逐帧跟随，积分子步长不超过 1/120 秒。绘制时保留小数网格位置，绝不能再次取整抵消平滑动画；移动中的坐标可保留一位小数，停稳后精确落到目标格点。遇到无关的新目标，先把旧框淡出到透明度低于 0.04，再替换位置并淡入新框，透明度缓动使用 1 - exp(-dt * 16)。最多保留三个槽位，连线透明度跟随两个端点中较低者，避免连线突跳。暂停时直接更新为稳定静帧，不连续安排淡入淡出动画。

绘制蓝色框、淡色填充、明显角标、坐标与细连线，指针或键盘聚焦时出现，离开后淡出。信号稳定时框可以稳定，但噪声或鼠标形变必须能改变检测位置；不能靠随机游走制造动态，也不能声称执行了真实 AI 推理。

7. 高清画布、动效与无障碍
每张卡片使用独立可见 canvas。让画布 backing width 和 height 等于画布自身的实际 CSS 尺寸乘以当前 devicePixelRatio 并取整，再设置 2D transform，使绘图坐标仍使用 CSS 像素。每个 requestAnimationFrame 帧都清空并重画。用 ResizeObserver 响应卡片尺寸变化，但不重新采样标志。即使 CSS 宽高未变，单独改变 DPR 也必须更新像素缓冲：绘制前比较当前 DPR 与缓存值，或使用变化后重新绑定的 resolution matchMedia 监听；不能只依赖 ResizeObserver。暂停动效时，DPR 或尺寸变化也应更新画布并补画一个静帧。验收时保持 CSS 视口尺寸不变，将 DPR 从 1 切到 2，确认像素缓冲翻倍且采样次数仍为一次。让高像素密度屏上的线条保持清晰。提供可键盘操作的动效开关，并保持 aria-pressed 状态准确；遵守 prefers-reduced-motion，默认静止。卡片可通过键盘聚焦并有实用的无障碍名称；canvas 仅作装饰，应从辅助技术中隐藏。支持触控，移动端触控目标要足够大。
